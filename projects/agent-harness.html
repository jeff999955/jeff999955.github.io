UBC Computer Vision Lab · M.Sc. · 2026

An agent harness that runs GPU experiments from code change to pull request

For my M.Sc. benchmark I had to port a long list of published methods and run them on three different compute providers. I built a Claude Code harness that does the repetitive loop (write the job, submit it, watch it, fix it, collect the results) and hands me a pull request to review, so researchers stop babysitting experiments.

The problem

The benchmark behind my WACV 2027 paper re-evaluates 11 published methods on 4 datasets. Each method has to be ported, packaged and run scene by scene on Slurm clusters with time limits, across a lab-owned cluster, UBC Sockeye and Compute Canada. Overall the project ran 110k+ Slurm jobs (about 15.8k GPU-hours). Most of the work is the same loop over and over: write a job script, submit it, wait, read the logs, fix what broke, resubmit, parse the numbers.

The loop

  1. I pick the question and approve the specEach task gets a written spec: what to build, how success is measured, and that the agent never merges.
  2. An agent session starts in its own git worktreeOne Claude Code session per task, so several tasks run in parallel without stepping on each other.
  3. It changes the code and writes the Slurm jobPorts a baseline or adds an experiment, then generates the batch script.
  4. It submits over SSH and monitors the jobPolls the queue, moves pending jobs to a free partition, and messages me on Slack when a job finishes.
  5. It reads the logs, fixes failures and resubmitsThe part researchers used to babysit
  6. It parses the results and opens a pull requestWith a required report: purpose, what was implemented, results and potential risks.
  7. I review and decide what to mergeEvery merge is mine; a hook blocks agents from merging their own PRs.

Guardrails

  • Hooks before every shell command block sudo, self-merges, a known-bad way of calling the Python environment, and writes to the wrong results folders. Deleting files with rm, find -delete or rsync --delete is denied outright.
  • Post-mortem rules. When an agent made a mistake, I wrote a rule so it wouldn't happen again, often tied to the specific incident.
  • Humans stay on the risky steps. Compute Canada needs multi-factor login, so submissions there stay with me.
  • The paper rebuilds itself. A hook recompiles the paper after each edit and sends me the PDF on Slack.

An example day

On 20 July 2026 I ran seven scouting tasks in parallel worktrees, one per candidate baseline. Four came back as go (PF3plat, SceneGen, Seva, AnySplat) and three as no-go. The staged go/no-go workflow they followed was distilled from my earlier port of Lyra.

Results

  • Parallel sessions opened 281 pull requests; 227 were merged after review.
  • The benchmark covers 11 baselines on 4 datasets (1.7k test views) and became a first-author WACV 2027 paper.
  • Engineering wins along the way: per-scene evaluation for CogNVS went from about 3.5 hours to about 21 minutes, and jobs sized from measured per-frame cost cut about 11.6k jobs down to 864.
